# ADR 0001 — 경로 추종에 Pure Pursuit를 쓴다

- **상태**: 채택
- **맥락**: v1 자율주행 스택의 경로 추종 제어기 선정

---

## 선택지

1. **NavMeshAgent** (UE5 내장 내비게이션)
2. **ROS2 Nav2** 스택
3. **Pure Pursuit 직접 구현** ← 채택

## 고른 것

Pure Pursuit를 직접 구현한다. 전체 스택은 실제 자율주행 구조를 따른다:

```
차량 모델 (Ackermann 또는 skid-steer, UE5 Chaos Vehicle 물리 기반)
  → 전역 경로계획 (A*, 차량 제약 반영 시 Hybrid A*)
  → 경로 추종 (Pure Pursuit)
  → 속도 프로파일 (곡률 기반 감속)
```

## 이유

**NavMesh를 버린 이유**
NavMesh는 게임 캐릭터 이동 방식이라 **조향각 제한, 최소 회전반경 등 차량 기구학을 무시**한다.
제자리 회전이 가능해지는 등, 무인체계 종사자가 보면 바로 알아본다. "게임 개발자"로 읽힌다.

**Nav2를 버린 이유**
학습 비용이 크고, 남의 스택을 쓰면 다시 귀속 문제가 생긴다.
**"Nav2가 있는 것은 알지만 제어기를 직접 이해하려고 구현했다"**가 더 좋은 답변이다.

**Pure Pursuit를 고른 이유**
- 핵심 로직이 50~100줄로 짧다
- 수식이 단순해 **화이트보드에 유도해서 설명 가능** — 무결성 원칙에 부합
- 실제 자율주행에서 쓰이는 기법
- **lookahead distance 튜닝 트레이드오프**(짧으면 진동, 길면 코너를 자름)가
  그 자체로 케이스 스터디의 "판단" 재료가 된다

## 포기한 것

- NavMesh를 썼다면 얻었을 개발 속도
- Nav2가 제공하는 코스트맵·리커버리 동작 등 성숙한 기능들
- 튜닝에 들어갈 시간 (lookahead distance는 직접 맞춰야 한다)
