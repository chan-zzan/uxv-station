# ADR 0005 — 스텁의 시간 인자 `t`는 절대 시각이 아니라 경과 시간으로 한다

- **상태**: 채택
- **날짜**: 2026-08-06
- **맥락**: `publish_loop`을 짜려면 `make_state(t)`에 넘길 `t`가 무엇인지부터 정해야 했다.
  그러다 `make_state` 안의 `time.time()` 호출이 순수 함수 약속을 깨고 있다는 것이 함께 드러났다

---

## 문제

`make_state`는 시각 `t`의 함수로 `VehicleState`를 만든다. 그런데 `timestamp` 필드만
함수 안에서 `time.time()`을 직접 불러 채우고 있었다.

```python
"timestamp": time.time(),   # 부를 때마다 다른 값
```

`make_state(0)`을 두 번 불러도 결과가 달라진다. 계산 결과가 인자 바깥의 것에 의존하니
같은 입력에 같은 출력이라는 성질이 깨진다. 검산표를 쓸 수 없고, 나중에 값이 이상할 때
스텁을 의심 대상에서 뺄 수 없다.

호출을 함수 밖으로 빼야 하는데, 그러려면 **`t`가 무엇인가**를 먼저 정해야 했다.
계약이 `timestamp`를 Unix 시각(초)으로 못박고 있어서, `t`의 정의가 `timestamp`를
어떻게 만들지까지 결정하기 때문이다.

## 선택지

1. **`t` = 프로그램 시작 후 경과 초.** `make_state(t, start_time)`으로 기준 시각을 인자로 받는다 ← 채택
2. `t` = Unix 절대 시각. `timestamp = t`로 끝나고 인자가 하나로 유지된다

둘 다 `make_state`를 순수 함수로 되돌린다. 갈리는 것은 순수함이 아니라 **재현성**이다.

| | (1) 경과 시간 | (2) 절대 시각 |
|---|---|---|
| 켤 때마다 시작 위치 | 항상 `(20, 0)` | 벽시계가 정함 — 매번 다름 |
| `t=0/10/20/30` 검산표 | 계속 유효 | 못 씀 |
| 껐다 켜면 | 출발점으로 되돌아감 | 궤적이 이어짐 |
| `make_state` 인자 | 2개 | 1개 |

## 고른 것

**`t`는 경과 초.** `make_state(t, start_time)`이 기준 시각을 인자로 받아
`timestamp = start_time + t`로 만든다.

`publish_loop`은 시작할 때 시계를 **두 번, 서로 다른 것으로** 읽는다.

| 저장 | 무엇으로 | 쓰는 곳 |
|---|---|---|
| `start_time` | `time.time()` | `make_state`에 넘겨 `timestamp` 생성 |
| `loop_start_time` | `time.monotonic()` | `t` 계산에만. `make_state`에 넘어가지 않는다 |

## 이유

- **스텁은 시뮬레이터가 아니라 테스트 픽스처다.** 브리지도 웹도 아직 없는 상태에서
  스텁의 유일한 임무는 "이 값이 나와야 정상"이라는 **기준점**을 제공하는 것이다.
  화면이 이상할 때 `(20, 0)`이 안 찍혔다고 바로 말할 수 있어야 한다.
  (2)를 고르면 버그가 나올 때마다 "지금 차량이 어디 있어야 정상이지?"를 먼저 계산해야 한다.
- **재현성이 물리적 사실성보다 우선한다.** 이 우선순위는 이미 `uxv-stub/README.md`에
  적어둔 것이고, 이 결정은 그 원칙을 시간 인자에까지 적용한 것뿐이다.
- **두 시계를 나눠 쓰는 편이 안전하다.** 경과 시간을 `time.time()`으로 재면
  NTP 보정이 시계를 뒤로 돌린 순간 뺄셈이 음수가 되어 루프가 망가진다.
  `monotonic()`은 뒤로 가지 않는다. 반대로 `monotonic()` 값은 기준점이 임의라
  남에게 보내면 의미가 없으므로 `timestamp`에는 쓸 수 없다.

## 포기한 것

- **재시작하면 차량이 순간이동한다.** 스텁을 껐다 켜면 궤적이 이어지지 않고
  `(20, 0)`으로 되돌아간다. (2)가 공짜로 주던 성질이다.
- **여러 스텁을 동시에 띄우면 위상이 제각각이다.** (2)라면 모두 같은 벽시계를 보므로
  자동으로 동기화됐을 것이다. v1은 차량 한 대라 지금은 문제가 아니다.
- `make_state`의 인자가 하나 늘었다. 호출부가 `make_state(t, start_time)`으로 길어진다.

## 다시 볼 시점

**두 성질 중 하나가 실제로 필요해지면 재검토한다.** 다만 그 시점은 아마 오지 않는다 —
"재시작해도 이어지는 궤적"과 "여러 대의 위상 동기화"는 작업 순서 [3] UE5 차량 물리에서
적분 기반 운동으로 자연히 얻는 것이고, 임시 픽스처인 스텁이 그것을 흉내 낼 이유가 없다.
