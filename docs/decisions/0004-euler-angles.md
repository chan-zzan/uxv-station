# ADR 0004 — 자세는 오일러각(yaw/pitch/roll)으로 싣고, pitch 범위를 ±π/2로 제한한다

- **상태**: 채택
- **날짜**: 2026-07-28
- **맥락**: 스텁의 `yaw` 정규화를 짜다가 "roll·pitch도 정규화해야 하나"를 따져보니,
  세 축의 정규 범위가 서로 다르다는 것이 드러났다

---

## 문제

계약은 `attitude`를 `{yaw, pitch, roll}` 세 숫자로 싣고, 범위를 전부 `-π ~ +π`로 적어뒀다.
그런데 **오일러각은 같은 자세를 여러 조합으로 표현할 수 있다.** 다음 둘은 물리적으로 동일하다.

```
(yaw, pitch, roll)  ≡  (yaw + π,  π − pitch,  roll + π)
```

말로 풀면 당연한 얘기다. "코를 100° 든다"는 수직을 지나 뒤로 넘어갔다는 뜻이고,
그건 "180° 돌아서서 코를 80° 들고 뒤집혀 있다"와 같은 자세다.

따라서 `pitch`가 `±π/2`를 넘는 구간은 **새로운 자세를 하나도 만들어내지 못한다.** 순수 중복이다.
범위를 안 좁히면 같은 자세에 여러 표현이 생기고, 두 상태가 같은지 비교할 수 없게 된다.

> **위도·경도와 같은 구조다.** 경도는 `-180 ~ +180`, 위도는 `-90 ~ +90`.
> 북위 100°란 게 없는 이유와 `pitch`가 ±90°인 이유가 정확히 같다.
> 그리고 극점에서 경도가 무의미해지는 것이 곧 **짐벌락**이다 —
> `pitch = ±π/2`에서는 yaw축(월드 z)과 roll축(차체 x)이 겹쳐 둘을 분리할 수 없다.

애초에 자세를 무엇으로 실을 것인가부터 다시 볼 필요가 있었다.
**ROS2 표준은 오일러각이 아니라 쿼터니언(`geometry_msgs/Quaternion`)이다.**

## 선택지

1. **오일러각 `{yaw, pitch, roll}`** ← 채택
2. 쿼터니언 `{x, y, z, w}` — ROS2 표준. 짐벌락·중복 표현이 없다
3. 회전행렬 3×3 — 숫자 9개. 논외

## 고른 것

**오일러각을 유지하되, 계약에 축별 범위를 명시한다.**

| 축 | 범위 |
|---|---|
| `yaw` | `-π ~ +π` |
| `pitch` | **`-π/2 ~ +π/2`** |
| `roll` | `-π ~ +π` |

## 이유

- **사람이 읽을 수 있다.** `yaw: 1.5708`은 보는 즉시 "북쪽"으로 읽힌다.
  쿼터니언 `{0, 0, 0.707, 0.707}`은 변환하기 전엔 아무것도 알 수 없다.
  이 프로젝트의 기준은 완성도가 아니라 **"설명할 수 있는가"** 이고,
  로그·일지·데모 화면에서 값을 직접 읽는 일이 계속 생긴다.
- **지상 차량은 짐벌락 구간에 가지 않는다.** `pitch = ±90°`는 차량이 수직으로 서 있다는 뜻이다.
  v1의 운용 범위 밖이고, 거기 도달했다면 그건 표현의 문제가 아니라 사고다.
- **운용 화면이 쓰는 값은 `yaw` 하나다.** 캔버스 아이콘 회전, 방위각 표시 둘 다 `yaw`만 필요하다.
  쿼터니언이면 그릴 때마다 오일러각으로 되돌려야 한다.
- **범위만 정확히 적어두면 중복 표현 문제는 사라진다.** 비용이 문서 한 줄이다.

## 포기한 것

- **ROS2 표준과 다르다.** [2]단계에서 ROS2나 UE5를 붙일 때 어댑터에서 변환해야 한다.
  다만 이건 이미 [ADR 0002](0002-coordinate-frame.md)에서 어댑터를 두기로 한 자리라
  변환 지점이 새로 늘어나지는 않는다 (좌표계 변환에 자세 변환이 얹힐 뿐).
- **`pitch = ±π/2`에서는 표현이 퇴화한다.** yaw와 roll을 각각 복원할 수 없고 둘의 차이만 남는다.
  오일러각을 쓰는 한 고칠 수 없는 성질이다.
- 자세를 보간(interpolation)해야 할 일이 생기면 오일러각으로는 곤란하다.
  현재 계약에는 보간 요구가 없다.

## 다시 볼 시점

**`pitch`가 수직에 가까워지는 플랫폼을 다루게 되면 이 결정을 재검토한다.**
그때는 계약의 `attitude`를 쿼터니언으로 바꾸고, 웹 표시 직전에만 오일러각으로 변환하는 쪽이 맞다.
v1의 지상 차량 한 대에는 과한 선택이다.
