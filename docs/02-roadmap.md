# 확장 로드맵 (v2~v4)

> **구현하지 않는다. 포폴 문서로만 존재한다.**
> 야망은 로드맵으로 보여주고, 실력은 완성품으로 보여준다.
>
> 출처: [uxv-station-roadmap.md](uxv-station-roadmap.md) 10장

---

## 버전별 계획

| 버전 | 내용 | 얻는 것 |
|---|---|---|
| **v2** | Unity 차량 추가 | 시뮬레이터 교체 가능 = 엔진 무관 인터페이스 증명 |
| **v2** | 짐벌 L2 자동탐지 | 화면 내 개체 자동 탐지·우선순위 |
| **v3** | 무인기 추가 | 지상+공중 **이종 플랫폼 통합관제** ← 최종 하이라이트 |
| **v3** | 통신 모의 확장 | 지연/손실, 재밍 등 |
| **v4+** | 교전 환경(공대공/공대지 등) | **문서로만. 구현 금지** |

### 짐벌 L2 구현 방향 (참고)

ML 비전이 아니라 **가상 개체 목록 + 콜라이더 다면 가시성 판정** 방식으로 구현한다.
저렴하고, 본인이 완전히 설명할 수 있기 때문이다.

## 아이디어 보관함

> v1 작업 중 떠오른 범위 밖 아이디어는 **구현하지 말고 여기에 적는다.**
> 작성자는 범위를 넓히다 미완성으로 끝내는 경향이 있다. **완성 > 화려함.**

| 날짜 | 아이디어 | 어느 버전에 어울리나 |
|---|---|---|
| 2026-07-24 | **다중 전송 지원** — 같은 메시지 계약을 WebSocket / ROS2 / REST로 각각 제공 | v2~v3 |

### 다중 전송 지원 (2026-07-24)

같은 계약을 여러 전송 방식으로 갈아끼울 수 있게 만들면,
**"메시지 계약이 전송 방식과 무관하다"**를 실제로 증명할 수 있다.
v2의 "시뮬레이터 교체 가능 = 엔진 무관 인터페이스 증명"과 뿌리가 같은 이야기다. 축만 다르다.

**v1에서는 구현하지 않는다.** 대신 핵심 로직과 전송 어댑터를 분리해 두어
나중에 어댑터를 하나 더 다는 일이 되게 한다 → [ADR 0003](decisions/0003-websocket-only.md)

주의할 점 두 가지:

- **REST는 텔레메트리용 대안이 아니다.** 요청-응답 방식이라 서버가 먼저 밀어주는
  10Hz 스트림에 맞지 않는다(폴링은 낭비이고 느리다). REST가 어울리는 것은
  "현재 설정 조회", "임무 목록" 같은 **단발성 조회**다.
  즉 WebSocket과 REST는 경쟁이 아니라 **보완**이며, 실무에서도 보통 둘 다 쓴다.
- **ROS2는 브라우저에서 쓸 수 없다.** 웹 구간은 계속 WebSocket이고,
  ROS2는 브리지 안쪽(브리지 ↔ 다른 ROS2 노드) 에 들어온다.
